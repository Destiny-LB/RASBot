# 自主演进

平台以 LLM 引导的单轮候选引擎为基础，并支持有预算的长期目标：依次探索执行指令、Skill 和脚本假设，可从被拒绝的历史候选继续开发，但始终与当前采用版本做独立配对比较。它是串行的有限多候选探索，不是并行种群搜索，也不会无限自动启动下一轮。

## 入口、样本与调度

工作台“自主演进”页选择 Agent、诊断依据、2～3 个不同评测任务与预算。页面推荐最近失败任务，尽量附带同任务的成功对照；没有失败时使用最近成功任务。至少一个评测任务不在本轮诊断证据中，但不保证它从未在历史实验中出现。

推荐不调用模型、不启动实验。任务池首次从具备 prompt 的目录建立，精度 Agent 存于 `.rasbot/evaluation-pool.json`，其他 Agent 独立保存；新任务不会静默加入。每轮记录选择策略、池内容和选定任务。

服务端每 5 秒推进，关闭页面不停止轮次，重启后继续观察已有会话。启动前固定父版本、模型、任务资产、评价政策及源码摘要；固定资产发生变化会使实验失效。修改平台代码前应结束活动轮次。

RASBot 的精度 Agent 现在支持版本化执行文件包，不再只演进执行指令。

## 源码版本与执行流程

1. 开始新一轮时，将旧版对应的可演进源码冻结为基线子版本。旧范围文件包也迁移为子版本，补齐核心文件并保留已有覆盖；当前范围版本直接复用。`baseline_source` 记录开始前采用的版本；拒绝候选不会改变它。
2. 改进器同时收到执行证据、父版本指令和源文件全文。响应可以包含 `file_changes`，键为相对路径，值为修改后的完整文件内容；省略或空对象表示不改文件，null 可删除辅助文件但不可删除核心入口。仍禁止改进会话直接调用工具，代码通过结构化提案进入版本管理。
3. 平台检查路径、文件类型、大小和 Python 编译语法，将变更合并为完整 `execution_files` 快照。所有内容参与版本哈希。语法检查不代表功能正确。
4. 基线和候选分别执行任务。每个执行会话在自己的 attempt 目录创建 `execution-package`，由 `EXECUTION_ROOT` 指向；`REPO_ROOT` 提供只读任务与文档。任务契约要求使用版本化脚本，版本化 Skill 全文直接载入契约。
5. 产物仍由原始仓库中的固定验收脚本独立检查。候选修改执行侧的 `prepare_atk_submission.py` 或 `verify_trigger_coverage.py` 不会改变平台验收入口。验收前检查执行文件包和原始验收脚本是否被改写。
6. 沿用配对评测、严格晋升和回退机制；晋升后新任务使用整个候选文件包。原 PrecisionTesting 仓库不会被发布覆盖。回退采用本轮冻结并实际评测过的基线。
7. 版本观测展示 Skill、脚本的逐文件 diff；演进记录展示候选源文件。



## 决策

仅由固定元评价决定晋升：候选通过独立验收与契约，辅助指标允许权衡，两轮反序配对的平均加权增益各不少于 1 分。耗时只用于预算与诊断，不参与晋升。基础设施异常、证据失效或复测预算不足时保留候选和证据，不采用候选。

策略实现集中在 meta_promotion.py；历史记录标识集中在 evaluation_policy.py。其他 Agent 必须提供显式决定函数，平台没有按通过数自动晋升的兜底。完整说明见 [评价与轨迹分析](evaluation.md)。

## 预算和版本

仍是单父版本、单候选。2～3 个任务初测需要 4～6 次执行；按需复测后上限 8～12 次。创建轮次时优先为首次配对执行分配相同会话预算，总预算仍限 60/120/240 分钟，复测不延长截止时间。默认 120 分钟；对耗时较长的任务可选 240 分钟；预算不足产生无结论，不能自动晋升。

复测列表与决策持久化，可恢复执行、取消、查看轨迹、回退。工作台分开展示初次评测和质量确认，并展示晋升类别与决策原因。质量配对证据保存在 `decision.pairs`；耗时保存在 trial 中。



## 评价边界与元评价

生成门槛见 [PrecisionTesting 接入](precision-runtime.md)。报告存在且非空不等于报告语义正确；生成效率也不等于数值覆盖或故障发现能力。两次配对复测不构成统计显著性证明。

`meta_evaluation` 仅记录评价器局限及建议，不进入候选执行指令，不修改本轮规则。影子指标、结构校准及只读审计见 [评价与轨迹分析](evaluation.md)。当前没有评价器自动演进、硬件可靠性评分；长期目标支持有限串行多候选与历史分支选择。

提案使用简体中文撰写诊断、执行指令和元评价建议；JSON 键、代码、路径与命令保持原文。初始提案通过结构化 JSON 提交；随后默认开启候选开发会话，允许修改、试跑和修复，见 [候选开发](candidate-development.md)。

执行文件包是版本副本隔离，不是操作系统沙箱。脚本继承 OpenCode 执行环境权限；文件完整性不能证明某脚本被调用，需结合工具轨迹检查。权限请求不会被平台自动批准。

## 持久化、接口与恢复

- `evolution_runs` 保存协议、模型、证据、候选、试验、决策及时间线。
- `versions` 保存内容寻址版本及父子关系；`champions` 按 Agent 保存采用版本。
- 每个任务保存指令、会话轨迹、验证日志和产物摘要；版本观测展示指令及源码 diff、关联评测与当前采用状态。
- `POST /api/evolution/start` 启动，参数包含 `source_ids`、`slugs`，以及可选模型、Agent 和预算；模型必须明确。
- `GET /api/evolution` 查询，`POST /api/evolution/tick` 单步推进，`POST /api/evolution/cancel` 请求停止，POST 均使用平台请求令牌。
- `POST /api/evolution/rollback` 传入已晋升轮次 `id`；当前采用版本仍为该候选时才能回退，历史任务不改绑。

网络不确定时不重发提案；`proposal_starting` / `proposal_unknown` 需要核查会话后处理。取消保持 `cancelling` 直到确认引擎终态。预算包括准备、等待和验证；它是调度预算，本地阻塞调用与停止确认可能超过截止时间。旧记录使用原始政策，历史分数不重算。

版本由演进流程写入，手动候选表单及 `/api/candidates` 已移除。代码更新后需重启平台，新轮次才加载新能力。

## 长期目标、探索与经验

工作台“长期演进目标”复用上方选择的 Agent、诊断依据和评测任务。每个目标限制 1～12 轮，每轮 60/120/240 分钟，总截止时间为轮数乘每轮预算加一分钟调度余量。暂停不重置截止时间。预算用完不等于目标达成。

策略 `bounded-sequential-hypotheses-and-archive-v1` 轮流提示执行指令、Skill、脚本方向；这些是探索重点，不是已证明的改进假设。隔轮可以选择本目标中最近被拒绝的候选作为开发父版本 `proposal_parent`。对照 `baseline` 始终取创建实验时当前采用版本；晋升前再检查采用版本没有变化。候选内容的父子关系反映开发来源，而不是混淆成对照来源。

每个实验仍需经过独立开发验收、正式配对评测及必要的质量确认。目标不会自动把无结论当作失败改进证据：失败、取消、基础设施问题会进入 `needs_attention`，需检查后继续。连续三轮无晋升或预算用完会停止。暂停会取消当前轮并等待停止确认；继续时创建下一轮，不重放原会话。

`campaigns` 持久化目标、预算、实验关联及状态。创建实验时原子写入目标 ID 和轮次索引，目标控制器重启时先根据归属恢复，避免“实验已创建、目标记录尚未更新”造成重复创建。当前服务为单进程控制平面，不支持多个服务进程同时调度同一数据库。

`experiences` 每轮只记录一次，包含成功、拒绝和失败结果、父版本、对照版本、决策、试验 ID 与评价器。下一轮读取当前 Agent 最近六项摘要；原始正式评测任务内容不进入经验提示。经验是实验观察，不是自动推导出的通用规律；历史晋升可能已回退。评测集跨轮复用，因此不能宣称存在永久未见保留集。

- `GET /api/campaigns`：目标列表。
- `POST /api/campaigns/start`：`objective`、`agent_id`、`max_rounds`、`round_minutes`，可选 `source_ids`、`slugs`、`model`。
- `POST /api/campaigns/control`：`id` 与 `action`（pause/resume/stop）。
- `GET /api/experiences?agent_id=precision`：带证据的经验记录。

调度每个 Agent 最多一个活动轮次；不同领域可建立各自目标，但目前没有 GPU/硬件资源池，也没有并行候选执行。源码仍使用内容寻址包，不依赖 Git worktree。这使现有小型包保持兼容；扩大到完整仓库前需补充 worktree 和真正的隔离执行器。

### 首轮优先预算与有限提案修复

新建演进按首次基线/候选配对次数分配执行预算，最大复测次数不再稀释首次比较预算。120分钟、两个任务、含开发阶段的配置，单次执行预算为1320秒（原660秒）；双方预算一致，整轮时限不延长。质量初次达标时，仅在剩余预算足够覆盖完整反序复测时启动，否则保存候选与初次证据，以inconclusive及confirmation_required结束，不晋升。尚未自动启动独立确认轮次，也未实现基于历史耗时的自动预算校准。

提案JSON/字段/源码格式校验失败可在原提案时间预算内最多修复两次，保留错误输出与原因。工具越界不会因此放行；修复请求结果不确定时保持proposal_unknown，不自动重发。现有已创建实验仍保留其固定策略。


### 晋升事务、源码差异与完成时间

晋升在同一BEGIN IMMEDIATE事务内重新核对采用版本、更新champions并保存实验终态，提交失败时共同回滚。新开发记录同时保留父版本到最终候选的完整源码差异，以及开发起点到结束的development_delta；历史缺少父版本哈希的记录保持not_recorded。

单任务预算到期前先同步引擎终态，再使用OpenCode最后idle事件的time.created判定完成是否在预算内；只有引擎时间有效且处于启动与当前时间之间才使用。无法确定时间时保留产物，以inconclusive结束，不宣称按时完成。整轮墙钟预算仍是硬上限，耗时诊断仍包含平台校验及观测耗时。


### 质量晋升与验证边界

不以速度换取晋升。保留生成质量五项指标及反序确认，耗时仅作预算和诊断。硬件实验通常昂贵且不可重放，未来接入必须另行定义实验条件、证据链及跨实验归因规则；平台当前没有硬件晋升策略，不会自动重放硬件实验。

按变更组件记录 contract_plan：脚本/文档触发结构正反探针；准备脚本对应固定资产等价；提示词对应生成与完整性检查。未实现的转换语义、触发覆盖语义和提示词事实语义测试明确记入 not_validated，不伪装成已通过。候选自带测试不能替代固定验收。

经验摘要保留晋升依据、失败原因与已验证阶段；没有配对评分的异常也保留诊断原因。影子审计使用实际评价器版本，是否测得风险覆盖按任务证据报告。

### 验收完整性与端到端计时修复

结构契约探针分别使用独立输入副本；正式工作区、被测输入、固定仓库脚本及平台源码在探针前后核对摘要，副本或正式资产被改写均拒绝通过。该机制为副作用检测，不是操作系统隔离。

新 trial 在工作区准备前持久化 pipeline_started。duration_seconds 覆盖准备、提示词生成、执行及验证，execution_seconds 保留模型派发至验证结束的耗时，preparation_seconds 记录二者差值。计时仍包含平台调度等待。没有准备起点的旧 trial 不回填猜测值，不能据此宣称效率收益。

开发验收以开发预算与整轮预算中较小的剩余时间建立共享单调时钟截止时间。固定/候选准备、固定验证、两个结构探针均按剩余预算设置超时；耗尽时按 budget_exhausted 结束，不发起修复重试。


### 硬验收与探针归因

候选必须具有明确的正式验收 passed=true，不能用质量分覆盖验收失败。缺失验收记录，或验收声称通过但必需工具链契约未运行时，判为证据不足。正式决策前重新读取任务验收结果，不复用过时的 trial 通过标记。基线的可比较业务失败不阻止对合格候选评测质量改善。

执行门槛和元评价共用 GENERATION_DELIVERABLES：正式规则、constraints、设计报告、覆盖账本、ATK 输入、trigger_library。ATK 输入由固定转换器重新生成后验收。

固定探针先运行且必须通过固定样例，随后运行候选探针。候选确定性的导入、语法、接口或输入处理异常记录为 candidate_interface_failure；超时、固定侧异常、未知退出码和完整性问题保持证据不足。两侧执行结果分开记录。失败出口也复查受保护资产，完整性异常优先于候选行为结论。


### 通用任务准入与综合质量晋升（v3）

所有具备固定任务资产和提示词的算子均可参加推荐与演进。无专项风险探针的任务，risk_coverage 保持未测，只比较固定权重下其余四项已测分（最高 70 分），不按比例补齐 100 分，也不宣称风险覆盖已验证。双方或各轮风险测量缺失不一致不能缩减评分范围以获得晋升。已知专项探针的测量失败也不能退回通用评分。

硬要求继续保留：候选正式验收通过、规则可物化和必要交付达标、固定资产完整、必要契约执行成功。辅助指标和单个任务退步不再一票否决，所有退步仍记入 regressions。每轮按任务平均计算固定权重增益，两轮各至少 1 分，反序复测后才晋升；成本不参与晋升。该 1 分门槛沿用已有默认值，尚非统计校准结果；两轮完成后记录基线重复评分绝对差，供后续校准，不自动修改阈值。

未知分布记为 not_measured；风险分仅表示已确认命中的保守下界，同时报告上下界。支持 float32/float16/bfloat16 等价 dtype 和 constant 列表；不把正态分布的均值或宽泛范围当作必然覆盖证据。结构合法性与数值风险仍是不同判断。

兼容接口明确为 verify_schema.validate_atk_structure(data) -> (errors, warnings) 以及核心脚本现有 CLI 参数。内部可重构，保留该薄适配入口即可；不是要求保留所有内部函数。未证实收益的候选继续保存为 retained_unproven，不替换采用版本。Step 2/3 仍为待验证效果。

新评价标识 precision-generation-weighted-v3，晋升标识 generation-quality-aggregate-v2；历史记录不重算，旧策略轮次不得跨评价器版本恢复晋升。
