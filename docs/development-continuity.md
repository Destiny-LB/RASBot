# 开发接力与证据驱动探索

候选开发在会话明确 idle 后，可因会话失败或独立开发验收失败接力到新会话。最多三个会话，共用原开发开始时间和整轮预算。未知提交状态不重放，保护资产被修改时不接力。

每次接力保存源码、内容哈希、开发父版本、独立检查及原会话引用；创建新会话前重新验证源码哈希。检查点仅证明源码范围和完整性通过检查，不代表开发验收或正式晋升。每次会话轨迹单独归档。当前不支持执行中的实时快照或未知请求自动恢复。

实验观察增加失败阶段、失败类别、修改组件、适用评价器与证据引用。查询从最近100条同Agent记录中按相关性排序返回6条，指定评价器时严格匹配；不向提案注入原始开发日志或正式任务身份。旧记录仍可读取但可能缺少结构字段。

长期目标不再按奇偶轮选择父版本。只从当前基线下、可比较且无人为干预的被拒候选中，优先选择通过数改善较大的候选；无合格候选则从当前采用版本开发。选择原因及证据轮次写入 campaign_context.selection。下一步假设按开发验收失败或正式评价不足确定，仍属于待验证假设。原有预算、连续无收益停止、独立评分和晋升政策保持有效。

验证范围：合成回归测试，不代表真实模型接力质量或硬件可靠性收益。
