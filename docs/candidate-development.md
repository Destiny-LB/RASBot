# 候选开发工作区

精度 Agent 的新建 Web/API 演进默认开启候选开发：

诊断提案 → 可编辑候选与诊断任务副本 → OpenCode 修改、运行、修复 → 源码冻结 → 独立配对评测 → 晋升或拒绝。

## 开发和评测的区别

- 开发时，`development/execution-package` 中的 Step 1 Skill 和允许的 Python 脚本可修改；临时测试放到 `scratch`。只提供首个诊断任务的全新工作区，不复用失败运行产物。
- 正式评测时，使用冻结后数据库版本中的完整源码，再创建独立任务工作区；开发日志和试跑结果不会计入正式分数。执行时改写冻结源码仍会失败。
- 开发源码必须满足原有路径、文件类型、大小、语法限制，不允许删除继承文件、链接或增加不允许的源文件。不得改变开发任务的保护资产、原仓库或固定评价器。

## 预算与恢复

开发预算为整轮的 20%，上限 15 分钟；不延长整轮截止时间，剩余预算平分给最大正式执行次数。60 分钟轮次分配 12 分钟开发；120 分钟轮次分配 15 分钟开发。

开发会话支持正常轮询、取消、预算超时中断；提交结果不明时保留 `development_unknown`，不重复发送。重启后从持久化状态继续。准备或创建会话途中崩溃需检查状态再取消，不能自动重复创建。

源码冻结前要求 OpenCode 会话成功结束、至少有一次完成的 shell 工具调用，并检查源码及任务资产。shell 调用只证明观察到执行活动，不代表测试正确或完整。新轮次额外执行平台独立开发验收：使用原仓库固定验收器检查诊断工作区完整产物，将结果写入 `development-check.json`，失败不冻结候选、不创建正式评测任务。检查包含在开发及整轮预算中。开发验收不代表能力提升，正式分数仍来自独立评测。

工作台展示开发阶段、开发任务、目录、会话和冻结时间。工具上下文保存在开发目录 `context.json`。开发阶段可能等待 OpenCode 权限，平台不会自动放行全部权限；可在 OpenCode 中处理相应会话，超时则停止本轮。

## 接口与边界

`POST /api/evolution/start` 可传 `development: false` 使用旧的提案后直接评测流程。支持文件演进的 Agent 在该接口默认开启；Python `Evolution.create` 为兼容旧调用默认关闭，需显式 `development=True`。

这是文件副本隔离、提示边界和完整性检查，不是操作系统沙箱；同机 OpenCode 权限仍可访问其他路径。开发指令禁止读取保留任务，但并未实现操作系统级保留集访问控制。当前不开放硬件操作，不改变评分规则，不自动晋升开发期间的临时版本。

本次测试覆盖开发后冻结、受保护资产变更拒绝、删除/非法文件拒绝、无试跑证据拒绝、超时取消、请求不明不重放及控制器恢复。真实模型开发与改进收益需另行运行实验验证。

## 文档副本与访问边界

开发会话的 `REPO_ROOT` 改为只包含参考文档的副本；唯一提供的任务工作区来自本轮首个诊断任务，不把整个任务仓库挂到开发参考路径。这减少意外读取保留任务，但没有改变同机 OpenCode 的操作系统权限，不能阻止已知路径访问。真正的保留集隔离和硬件隔离仍未完成。

平台新增独立开发验收后，开发会话必须生成完整规则、设计报告和覆盖账本。仅输出 shell 成功或测试通过文字不构成验收证据。没有开启开发阶段的旧流程仍按原方式进入正式评测；旧轮次保持其冻结政策。
